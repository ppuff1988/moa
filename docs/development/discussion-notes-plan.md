# 討論順序與私人筆記實作計畫

> 實作計畫 | 更新日期：2026-09-20 | 狀態：已實作，驗收紀錄見文末

讓玩家在外部語音或現場討論時，快速記錄每人的說法，並對照行動先後自行推敲真假。手機以玩家收合列表為主，同一份私人筆記可切換成獸首對照。

分支：`feat/discussion-notes`，從當時工作分支 `hotfix/room-presence` 的 `67e4934` 建立。沿用使用者要求的 `feat/` 命名。已完成座位模式、討論順位與私人筆記。依[工作流程](../WORKFLOWS.md)，後續 PR 原則上以 `dev` 為目標，建立 PR 前須核對基底差異，避免把既有 hotfix 重複納入。

## 1. 已確認需求

- 建房時選擇隨機座位（預設，適合線上）或依現場座位（房主排列）。兩種模式均在開局後固定三輪，重新加入保留原位。
- 實體局由房主在大廳按現場左手方向排列，大家核對自己的左右鄰居；玩家名單改變時須重新確認。座位模式與線上投票、自動選角分開設定。
- 首輪首位行動者另外隨機選出；行動期間仍由玩家指定下一位。
- 每輪從最後行動者的左鄰開始發言，沿固定座位繞一圈，最後行動者壓軸。
- 只顯示整輪發言順序，不追蹤目前發言者；討論後由房主開始投票。
- 發言透過外部語音或現場進行。每位玩家自行記錄，只有本人可讀寫，房主也不能查看他人筆記。
- 獸首選單為「真／偽／無法鑑定／被攻擊（無法鑑定）」，另有「未記錄」。每人可記錄多個獸首。
- 「被攻擊」從獸首選單選取，代表玩家自述整輪無法鑑定；會清除該輪獸首說法、保留備註。不是系統證實的攻擊狀態。
- 玩家列表預設依發言順序，可切換依行動順序；每個人旁直接顯示行動順位。
- 獸首對照也顯示說話者和行動順位，支援投票時查閱與三輪回看。
- 系統不自動判定謊言，不按角色技能限制手動筆記，也不把筆記當成實際鑑定結果。

## 2. 設計參考與手機配置

[最新版手機示意圖](assets/discussion-notes-mobile-concept.png)為內建 imagegen 根據現有介面風格與素材生成的設計參考，不是已實作截圖。

畫面順序：現有房間／本人身分 → 當輪與座位入口 → 單列四獸首與本人鑑定 → 預設收合的行動順序 → 筆記視圖切換 → 私密與儲存提示 → 排序 → 玩家列表 → 房主開始投票。

### 2.1 玩家筆記

- 主要切換為「按玩家記錄／按獸首對照」，次要切換為「依發言／依行動」。
- 同時展開一位玩家，其他列顯示已記錄的獸首與狀態摘要。
- 明確標示發言順位與行動順位。例如「發言 ① 小安｜第 3 位行動」。依行動排序時仍保留原本發言順位，不用陣列索引改寫順位。
- 點獸首狀態開啟底部選單：真、偽、無法鑑定、被攻擊（無法鑑定）、清除紀錄。
- 被攻擊套用整輪；改選其他狀態或清除紀錄會取消被攻擊，其餘獸首回到未記錄。備註不受影響。
- 排序／視圖切換保留展開的玩家與草稿，不因伺服器更新打斷輸入。

### 2.2 獸首對照與回看

- 每個獸首可展開所有玩家的說法，預設依行動順位排列，未記錄者明確標示。
- 每筆說法保留姓名、顏色、行動順位；同一筆資料在兩視圖立即一致。
- 「我的鑑定」另區顯示本人已取得的實際結果；從現有權限過濾後的鑑定資料取得，不從獸首真值欄位自行推導。
- 提供回合選擇，只能查詢已進入討論的回合。選看歷史回合不更動主遊戲的 `currentRound` 或投票目標。
- 討論頁直接嵌入；投票、結果與鑑人階段可由「私人筆記」入口打開同一組元件。返回投票保留原有籌碼分配。
- 座位入口在開局後的行動階段也可使用，讓玩家核對固定座位及左右鄰居。

### 2.3 示意圖轉成實作時的修正

- 示意圖的六人行動列在窄手機須換行，不能縮字或產生整頁水平捲動；同時支援七、八人與長姓名。
- 示意圖備註「小美先說鼠偽，小安後說鼠真」混淆了兩種順序。正確範例改為「第 1 位行動的小美說鼠偽；第 3 位行動的小安說鼠真」。正式空白筆記不預填範例。
- 編輯中的玩家不代表目前發言者。介面不加入發言完成、下一位或計時器。
- 沿用現有色彩與獸首圖片，觸控區至少 44px，狀態以文字辨識，底部選單與按鈕避開手機安全區及鍵盤。
- 底部選單有明確關閉方式、焦點管理和鍵盤操作；抽屜關閉後回到原觸發位置。

## 4. 座位與順位模型

### 4.1 固定座位

- 在 `games` 增加 `seatingMode`（random／manual，預設 random）及 nullable `seatOrder` JSON，內容是同局 `gamePlayers.id` 陣列。
- 陣列方向明確定義為「每一位的下一項就是其左鄰」，尾端回到首項；座位圖標出方向，所有人看到同一個排列。
- 隨機模式使用現有洗牌工具，於進入 `playing` 時產生一次；與首位行動者抽選分開。
- 現場模式由房主以大廳上下移動按鈕排序、確認儲存；以房主為起點只是方便核對，圓圈可旋轉而不改變左右關係。伺服器確認完整名單，開局後拒絕改位。未儲存調整時大廳會提醒先確認。
- 手動選角與自動分派都在既有交易內完成，重複開局請求不得重排或部分寫入。
- 三輪、斷線、離開再加入均不更動；以穩定 player ID 而非顏色／姓名綁定。

### 4.2 衍生順序

1. 用 `buildRoundPlayerOrder` 取得該輪正序行動名單與 `actionPosition`。
2. 僅在行動完成進入討論後，取 `actionOrder[0]` 為該輪最後行動者。
3. 找出他在 `seatOrder` 的索引，從下一項開始循環取得所有玩家，產生 `speakingPosition`。
4. 座位編號、行動順位、發言順位各有欄位，不以目前列表排序位置取代。

驗收範例：固定左向座位 `[小安, 小美, 阿哲, 小晴, 阿凱, 小明]`；行動正序 `[小美, 阿凱, 小安, 阿哲, 小晴, 小明]`；發言正序 `[小安, 小美, 阿哲, 小晴, 阿凱, 小明]`。

### 4.3 舊局與缺資料

新增欄位允許 null，migration 不替已開始的遊戲憑空建立座位。舊局仍可用私人筆記及行動排序，發言排序與座位入口提示「此局未建立座位」。新局一律完整建立座位。

缺漏、重複 ID 或找不到最後行動者時不猜順序；回傳可識別的不可用狀態。明確離房玩家仍保留座位及歷史行動順位，遊戲推進沿用既有等待重新加入規則。

## 5. 私人筆記資料與 API

### 5.1 保存方案

採伺服器保存，讓重新整理、重新加入與同帳號換裝置能取回已儲存的筆記。每份資料歸屬於「遊戲＋回合＋筆記擁有者＋被記錄玩家」。

新增 `game_discussion_notes`，每位擁有者對每位玩家每輪最多一列：

| 欄位                   | 用途                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------- |
| `gameId`、`roundId`    | 綁定同一遊戲與回合                                                                  |
| `ownerPlayerId`        | 筆記擁有者，後端由登入身分決定                                                      |
| `subjectPlayerId`      | 被記錄說法的玩家，可為本人                                                          |
| `artifactClaims`       | 以獸首 ID 為 key 的小型 JSON；值限 `genuine`、`fake`、`unable`，省略 key 表示未記錄 |
| `claimedAttacked`      | 整輪自述被攻擊，預設 false；由選單操作，非獨立勾選                                  |
| `memo`                 | 自由文字，預計上限 500 字                                                           |
| `version`、`updatedAt` | 避免多分頁覆蓋與顯示儲存狀態                                                        |

建立 `(roundId, ownerPlayerId, subjectPlayerId)` 唯一索引及必要外鍵。遊戲、回合、擁有者、對象與獸首須經伺服器驗證同局／同輪；清除最後一項也可保留空白列與版本。清除遊戲的既有 SQL／測試 fixtures 必須納入新表依賴。

### 5.2 API 契約

| 端點                                            | 回傳或修改內容                                                                                  |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `GET /api/room/[name]/discussion?round=N`       | 公開座位、該輪公開行動與發言順序、可回看回合、當輪獸首 ID／名稱；本人鑑定僅從本人的行動紀錄提取 |
| `GET /api/room/[name]/discussion-notes?round=N` | 僅回傳登入玩家擁有的該輪筆記與版本                                                              |
| `PATCH /api/room/[name]/discussion-notes`       | 指定 round、subjectPlayerId、expectedVersion，修改單一獸首說法、攻擊註記或備註                  |

另有 `GET /api/room/[name]/seating` 供全員核對座位，`PATCH` 僅接受房主的完整 `seatOrder`，且限現場模式開局前使用。

PATCH 筆記採欄位級操作：獸首可設三種值或清除，不用整份筆記覆寫其他欄位。owner 不接受客戶端指定。新筆記用 expectedVersion 0，以唯一索引處理同時建立；既有列在遊戲交易鎖內檢查版本，成功回傳新版本。

### 5.3 權限與資料界線

- 所有端點沿用 `verifyPlayerInRoom`；未登入、已離房或其他房間的玩家不能讀寫。
- 讀寫必須以登入者的 player ID 限定 owner；房主不具有額外讀取權限。
- 私人內容不混入公共 players／round-status／Socket 廣播，回應使用 `Cache-Control: private, no-store`，PWA 不快取私人 API。
- 公開討論 API 使用欄位白名單，不回傳角色、陣營、其他人的鑑定、真實攻擊／封鎖或未公開獸首真值。
- 不允許讀取預先配置但尚未開始的回合獸首。座位可在 action 階段讀取，該輪最終發言順序與筆記待進入 discussion 才開放。
- 遊戲進行中，可編輯所有已進入討論的歷史回合；finished／terminated 時提供唯讀回看。其他人明確離房不阻擋本人保存筆記，但既有遊戲推進仍暫停。
- 備註以文字渲染，驗證長度、JSON 大小、enum、整數 ID、欄位白名單與同局關係。

### 5.4 自動儲存與失敗處理

- 狀態選擇即排入儲存；文字輸入約 500ms debounce，中文組字期間不送出未完成文字。
- 每個筆記列循序送出修改，保留待送欄位佇列並合併連續文字修改；舊請求回應不能覆蓋較新的輸入或清掉其 dirty 狀態。
- 顯示「儲存中／已儲存／尚未同步・重試」。只有伺服器確認最新修改後才顯示已儲存。
- 未同步草稿可暫存 sessionStorage，key 包含 userId、gameId、round、subjectPlayerId；恢復時核對身分與版本，登出清除。儲存不可用時保留記憶體草稿並顯示未同步狀態。
- 多分頁同列版本衝突回 409，保留本地輸入，提供使用雲端版本或保留本次修改的處理方式，不靜默覆寫。
- 切換視圖、排序與回合不丟棄修改；切換階段仍可完成已開放回合的保存。遊戲結束造成保存被拒時保留草稿並提示。
- 本版不建即時跨裝置同步系統；換裝置可讀到已保存資料，並以版本檢查保護同時編輯。

## 6. 元件與狀態拆分

新增元件放在 `src/lib/components/game/`，盡量讓大型遊戲頁只負責組裝：

| 預計元件／模組                        | 職責                                                              |
| ------------------------------------- | ----------------------------------------------------------------- |
| `DiscussionPanel.svelte`              | 討論區、回合切換、視圖與排序，接上原房主開始投票操作              |
| `DiscussionNotes.svelte`              | 玩家收合筆記、狀態選擇、攻擊註記、備註                            |
| `ArtifactClaimsView.svelte`           | 從同一份筆記衍生獸首對照，標示行動順位                            |
| `SeatOrderDialog.svelte`              | 固定圓桌、座位方向、本人與左鄰；使用原生 dialog 管理焦點及 Escape |
| `discussionNotes.ts`（store factory） | 以遊戲與登入者隔離的筆記狀態、自動儲存、草稿與衝突處理            |
| `game-discussion.ts`（server）        | 公開討論資料組裝與私人筆記服務，避免路由內堆積邏輯                |

通用的順位衍生、筆記型別與排序純函式放在既有 turn-order／types／utils 相應位置。排序只是衍生陣列，編輯綁定穩定 player ID。筆記 store 不在 SSR 模組全域共用，避免跨請求混入其他使用者資料。

## 8. 測試與交付門檻

### 8.1 順位與開局

- 座位 wrap-around、最後行動者在首／尾位置，以及三輪不同最後行動者。
- 行動倒序轉正序、沒有 `gameActions` 的玩家仍有順位、無效座位／未知 ID 不捏造順序。
- 固定亂數來源測試洗牌與集合完整性；不以「每次都必須不同」這類不穩定斷言驗收。
- 手動／自動分派 × 線上／房主計票模式都支援討論，兩種設定與筆記互相獨立。
- 重複開局、離開再加入、下一輪與舊局 null 座位。

### 8.2 私密與保存

- A 寫下 B 的說法，B、房主與其他房間成員無法讀到 A 的筆記。
- 篡改 owner／subject／artifact／round、未來回合、無效狀態與超長備註皆有 API 行為測試。
- 被攻擊與鑑定說法互斥，整輪同步且可修正；備註保留。一般清除單一獸首不影響其他獸首。
- 刷新、跨輪回看、網路失敗重試、快速連續修改、多分頁衝突、過期回應與登出清除草稿。
- API 回應及公共 Socket payload 不包含他人私密資料。

### 8.3 UI 與完整路徑

- 元件測試覆蓋玩家／獸首視圖同步、兩種排序、順位標籤、展開狀態及儲存提示。
- Playwright 以兩個獨立登入 context 驗證私人隔離，並以 375px、390px、430px 寬度檢查六至八人、長姓名、鍵盤與橫向畫面。
- 實際跑開局 → 行動 → 討論記錄 → 投票回看 → 次輪回看上一輪；確認原籌碼分配及提交限制不受影響。
- 確認 focus、文字放大、reduced-motion、按鈕安全區與無整頁水平溢出。
